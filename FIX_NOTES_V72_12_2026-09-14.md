# Catatan Perbaikan v72.12 (verifikasi independen atas klaim v72.11)

Diverifikasi dengan menjalankan langsung (npm ci, tsc, vite build, 57 file tests_core satu per satu), bukan membaca laporan v72.11 apa adanya.

## Klaim yang TERBUKTI BENAR
- 57/57 file di tests_core exit 0 saat dijalankan satu per satu.
- Dependency lock: 258 package resolved via scripts/verify-dependency-policy.mjs — cocok.
- Static manifest: 178 file, 0 static check (bukan "0 gagal" — memang tidak ada static check yang didefinisikan di manifest ini).
- typecheck:core (tsc --noEmit) PASS.
- ClientsView memang read-only murni terhadap tabel trace-clients (tidak ada RPC insert/update/delete client di manifest migrations manapun).
- Marketing/KPI/SOP/Action Plan memang cuma dipakai sebagai import logic di layar lain (mis. KPI engine dipakai di dashboard, SOP di Business Twin board) — bukan layar mandiri. Klaim "belum jadi layar aktif" akurat.

## Klaim yang KELIRU / tidak lengkap — DIPERBAIKI di sini
1. **Root cause Vite build gagal BUKAN Node version.** Node 22.22.2 di environment audit ini cocok persis dengan `engines` di package.json, dan build tetap gagal. Penyebab sebenarnya:
   - `src/core/financeReport.ts` melakukan `await import('exceljs')` tapi `exceljs` tidak pernah ada di `package.json`/`node_modules`. Ini bukan cuma error TypeScript — fitur ekspor Excel-dengan-gambar akan **crash runtime** di production kalau dipanggil user, terlepas dari versi Node.
     → Fix: `npm install exceljs@4.4.0 --save`, sekarang tercantum di dependencies.
   - `src/core/fileIntakeAdapters.ts` memanggil `page.render({ canvasContext, viewport })` untuk OCR fallback PDF. Versi `pdfjs-dist@5.4.54` yang terpasang mewajibkan properti `canvas` eksplisit di `RenderParameters`, bukan cuma context-nya.
     → Fix: tambah `canvas` ke parameter render.
   - Setelah dua fix ini: `npm run typecheck:react` bersih, `npm run build:react` sukses (vite build lengkap, dist/react ter-generate), dan 57/57 tests_core tetap PASS. Ini verifikasi end-to-end, bukan klaim.

## Masih PARTIAL (butuh keputusan scope, bukan bugfix kecil)
- **Client CRUD**: perlu RPC/migration baru (insert/update/delete trace-clients dengan RLS scope), belum ada satupun di supabase/migrations. Ini pekerjaan fitur baru, bukan tambal bug.
- **Stock opname/reconciliation Inventory**: belum ada tabel/RPC untuk selisih stok fisik vs sistem.
- **Labor & OPEX detail (payroll, subledger)**: masih level kategori record seperti yang dilaporkan.
- **Marketing/Content/KPI/SOP/Action Plan sebagai layar mandiri**: core logic ada, UI khusus belum — akurat sesuai laporan v72.11.

Keempat item di atas butuh spesifikasi (skema tabel, field wajib, siapa yang boleh apa) sebelum bisa dieksekusi — bukan sesuatu yang bisa "diperbaiki" tanpa keputusan desain lebih dulu.
