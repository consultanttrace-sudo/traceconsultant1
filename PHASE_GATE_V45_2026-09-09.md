# TRACE Phase Gate v45 — Code Hardening & Release Gate Strengthening

## Concrete root causes found and fixed

### 1. Anti-overwrite guard was still fail-open despite v44 intent
- Evidence: `saveData()` threw `TRACE_OVERWRITE_GUARD_UNVERIFIED`, but the surrounding `catch` logged the error and then continued into the cloud upsert.
- Root cause: exception handling accidentally converted a safety failure back into an advisory warning.
- Fix: verification failures now return `false` immediately; the cloud write is not attempted.
- Prevention: regression test asserts both the guard error and the hard-stop path.

### 2. Acquisition social fetches had no request deadline
- Evidence: `acq-social-enrich.js` and `acq-social-intel.js` called `fetch()` directly.
- Root cause: public-URL validation protected the destination, but there was no request-level cancellation/deadline.
- Fix: both flows now use a bounded `fetchPublicUrl()` with a 7s timeout and at most 3 redirects.
- Prevention: static contract test requires the bounded public fetch.

### 3. Redirect-based SSRF bypass was possible after initial URL validation
- Evidence: `_url.js` validated the initial hostname, while social fetches used `redirect:'follow'`.
- Root cause: a public URL can legitimately redirect to a private/link-local/cloud-metadata target.
- Fix: redirects are now manual, every `Location` is revalidated with DNS/IP checks, and the chain is bounded.
- Prevention: `test_ssrf_redirect_guards_v44.mjs` checks the security contract and canonical/legacy parity.

### 4. Release runtime was not pinned
- Evidence: browser harness requires Node 22.22.2+, while the audit environment is Node 22.16.0.
- Root cause: project did not declare a single release runtime.
- Fix: added `.nvmrc`, `engines`, and `packageManager` pinning release execution to Node 22.22.2 / npm 10.9.x.
- Prevention: release-check blocks below the pinned runtime.

### 5. Floating dependency versions remain intentionally blocked
- Evidence: root `package.json` still uses `latest` and has no root lockfile.
- Root cause: exact dependency resolution cannot be truthfully generated in this offline environment.
- Correct solution: resolve exact versions in a network-enabled controlled environment, commit the generated lockfile, then run `npm ci`.
- Prevention: release-check now blocks both missing lockfile and floating `latest` versions.
