# TRACE Phase Gate v44 — Persistence & Workflow Integrity Hardening

## Concrete fixes implemented

### 1. Cloud persistence timeout now cancels the real request
**Evidence:** legacy `saveData()` previously used `Promise.race()` around the Supabase write.
**Root cause:** the timeout stopped awaiting the promise but did not cancel the underlying HTTP operation.
**Risk:** a late network response could still mutate cloud state after the UI had already handled a timeout.
**Fix:** `AbortController` + Supabase `.abortSignal()` + explicit timeout cleanup.
**Prevention:** persistence regression contract requires a real abort signal and timeout path.

### 2. Anti-overwrite verification now fails closed
**Evidence:** the previous guard continued when the pre-write verification query returned an error.
**Root cause:** safety verification was treated as advisory instead of a prerequisite.
**Risk:** a failed read could be followed by an unsafe read-modify-write.
**Fix:** verification failure throws `TRACE_OVERWRITE_GUARD_UNVERIFIED`; the write is not attempted.
**Prevention:** regression contract asserts the fail-closed behavior.

### 3. Local recovery is no longer reported as successful cloud persistence
**Evidence:** the fallback stored data locally and returned `true`.
**Root cause:** the boolean contract represented local recovery as if the authoritative team database had accepted the write.
**Risk:** downstream workflows could advance while team data was actually unsynchronized.
**Fix:** local recovery remains available, but `saveData()` returns `false` until cloud persistence succeeds.
**Prevention:** persistence contract explicitly rejects local recovery as an authoritative success.

### 4. Operational job state transitions are database-enforced
**Evidence:** `trace_jobs.status` had an enum-like CHECK constraint but no transition integrity.
**Root cause:** valid states existed without enforcing the legal lifecycle between them.
**Fix:** additive migration `009_trace_workflow_integrity_guards.sql` rejects impossible status jumps.
**Prevention:** recovery must use explicit `RESUMABLE` transitions.

### 5. Checkpoint sequence is database-enforced
**Evidence:** `UNIQUE(job_id, sequence_no)` prevented duplicates but allowed out-of-order checkpoints.
**Root cause:** uniqueness is not the same as monotonic recovery ordering.
**Fix:** migration 009 enforces increasing sequence numbers per job.
**Prevention:** recovery source cannot silently move backwards.

### 6. Data Intake review/approval sequence is database-enforced
**Evidence:** clients could previously update status values within the allowed enum without a workflow transition guard.
**Root cause:** status vocabulary existed without ordered state semantics.
**Fix:** migration 009 enforces draft → reviewed → approved, with explicit rejection/re-draft paths; committed remains server-only.
**Prevention:** approval state cannot be fabricated by arbitrary status updates.
